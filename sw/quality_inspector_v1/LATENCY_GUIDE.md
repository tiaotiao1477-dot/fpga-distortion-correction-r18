# 硬件延迟测量接口使用说明

“硬件延迟 → 测量”使用统一时间戳协议；连接支持相应能力标识的固件后采集。外部仪器结果可使用“导入外部延迟CSV”按钮导入。

## FPGA统一时间戳与帧ID

测量使用CRC保护的A9遥测，由上位机匹配帧记录并统计。

连接后点击“硬件延迟”的“测量”，可选择每角度300或1000帧。软件先明确应用并确认真实标定0°作为安全基线，再自动测试0°、15°、45°、90°。每角度预热30个有效对应源帧，再收集目标样本。正常结束恢复已确认的0°；若外部程序改变配置或ACK未知，停止恢复写并保留原始证据及错误。测试期间不要同时打开旋转控制台。

结果保存全部A9二进制原包、分角度JSON、逐帧CSV和延迟曲线。界面显示平均值和各组最高P95；具体每角度平均/最大/P95、输入/源/结果FPS和视频掉帧、遥测缺样见“结果”。这些值只能来自新板卡时间戳，不使用电脑收包耗时。

空队列状态包处理：A9在没有完整帧记录时仍回复状态，其`record_valid=false`且事件配置版本为0。软件继续核对epoch、运行状态、命令序号、Gamma和测量角度，但不把这种包计入延迟样本，也不将默认版本0与角度ACK版本比较。有效帧记录仍必须匹配实际配置版本。持续没有有效记录会明确超时，不能据此报告延迟已测得。

```text
DVP输入帧开始 T0 ──> 图像校正/DDR ──> 完整结果帧可提交 T1 ──> HDMI最终输出帧首有效像素 T2
          └────────────统一64位125 MHz计数器时间域────────────┘
帧ID：输入帧 → 处理/DDR slot或tag → HDMI显示切换；遥测UART只读报告，不参与视频计时
```

- 对每帧定义并记录：`T0` 为输入DVP首个有效像素对应帧开始；`T1` 为完整结果帧写入DDR且可提交的时刻；`T2` 为最终HDMI输出端DE首个有效像素对应帧开始。主要延迟可报 `T2-T0`；另报 `T1-T0` 与 `T2-T1` 便于分解。
- 可另记输入`lastpixel`时刻，以分离整帧采集/等待时间与后续处理、显示等待。所有事件定义必须在报告中固定说明。
- 以统一64位、125 MHz计数器计时，tick为8 ns。跨时钟域事件须用事件同步、稳定保持后同步或异步FIFO等可靠CDC方法传递；不能直接异步采样64位总线。接收域看到事件存在同步延迟和量化误差，因此8 ns只是计数器tick，不能宣称物理测量精度就是8 ns；需说明事件路径延迟、同步误差和量化误差。
- 帧ID必须从输入贯通处理slot/tag直到HDMI显示切换，才能匹配同一帧。每帧只统计该帧首次实际显示的`T2`；同一帧后续重复刷新另列统计，不能混入首次显示延迟。
- 上位机经UART采集帧ID及`T0/T1/T2`差值，汇总平均值、最大值、P95、有效FPS和丢帧/缺帧。UART不进入计时链；遥测缓冲满时丢弃遥测并递增丢遥测计数，不能阻塞视频处理或显示。
- 预热30帧后，收集300–1000个**成功匹配的有效帧样本**。超时、abort、缺少对应事件的帧需单独计数/报告，不算作有效延迟样本，也不能静默丢掉。报告须写明P95算法（例如排序后采用最近秩法或插值法）及具体规则，确保可复算。
- 分别在0°、15°、45°、90°校正角度记录；同时报告各角度的有效样本数、超时/abort/缺样和FPS/drop，勿将各角度混合成一个延迟分布。
- 此测量边界不含传感器曝光、外部显示器响应/扫描、HDMI采集卡及其电脑预览。若今后要评估光到光，需另做独立测量。

板卡须支持能力标识000f0007。时间戳测量允许Gamma AUTO；清晰度前后比较则由固件在帧边界固定恒等Gamma并确认实际应用，结束按ACK所有权恢复原模式。

## 备选方法：手机高速摄影（光到光）

此方法可快速估计包括摄像头、FPGA处理、HDMI链路和物理显示器的整体响应。固定手机，让同一画面同时拍到被测摄像头看到的LED和物理HDMI显示器；不要用电脑预览作为显示端。

```text
被测摄像头看到的 LED ──> FPGA ──HDMI──> 物理显示器
          ↑ 同一手机画面同时拍到 LED 和显示器 ↑
```

让LED产生清楚的亮/灭变化，逐次找出LED变化帧与显示器首次显示对应变化的帧。按 `延迟(ms) = 帧差 × 1000 / 实际帧率(fps)` 计算并重复至少10次。手机标称帧率未必是真实帧率，视频可能为可变帧率；优先按原片时间戳差计算，否则核实原片实际帧间隔。无法核实时注明不确定度，不能将标称fps结果写成精确值。误差需考虑帧采样量化（约一个或数个帧间隔）和显示扫描/刷新差异。若拍电脑预览，还会包含USB、操作系统和预览链路延迟，不能称为FPGA硬件延迟。

## 导入CSV

复制 `latency_template.csv` 表头，每次真实测量一行：

```csv
latency_ms,method
真实测得的毫秒数,手机高速摄影；LED到物理HDMI显示器；按原片时间戳计算
```

将占位说明替换为真实数值和方法后再导入。`method` 写清测量边界、事件/帧匹配方法和时间依据；保留原始记录以便复核。不要填预览延迟、指令ACK延迟、未实现方案的假数据或未经测量的示例值。
